무료 호스팅에 올린 회사 홈페이지, 무엇이 문제일까 — 우리 홈페이지를 직접 옮긴 기록

2026-11-19 · 소통마케팅센터
#홈페이지호스팅#GitHubPages#CloudflarePages#홈페이지보안#네임서버변경#홈페이지이사#소통마케팅센터#제천홈페이지제작

우리 회사 홈페이지가 계획과 달리 무료 진열장(GitHub Pages)에서 바로 나가고 있었습니다. 판매 페이지가 붙은 사이트를 무료 진열장에 두면 약관 위험과 보안 등급 문제가 생깁니다. 그래서 하루 만에 Cloudflare Pages로 옮겼습니다. 이 글은 그 과정에서 겪은 문제·고민·해결을 순서대로 적은 기록입니다.

이 글은 우리 회사 사이트(sotongmk.com)를 옮기며 실제로 확인한 내용만 담았습니다. 화면 사진의 계정 정보와 열쇠(토큰) 값은 가렸습니다.

1. 무엇을 발견했나요?

판매 페이지를 손보다가 보안 점검을 돌렸는데, 보안 항목에서 FAIL이 6건 나왔습니다. 원인을 따라가 보니 홈페이지가 어디서 보이고 있는지가 계획과 달랐습니다.

  • 8월에 만든 계획서: 글·사진 파일은 GitHub 저장소(창고)에 두고, 손님에게 보여 주는 일은 우리 서버(진열장)가 1분마다 파일을 가져와서 한다.
  • 11월 19일에 확인한 실제: 홈페이지 응답 머리글이 Server: GitHub.com이었고, 주소도 GitHub Pages 서버를 가리키고 있었습니다. 창고가 진열장 노릇까지 하고 있었던 것입니다.

손님 눈에는 아무 차이가 없었습니다. 사이트는 잘 열렸고, 글도 잘 올라갔습니다. 그래서 몇 달 동안 아무도 몰랐습니다.

2. 겉으로 멀쩡한데 왜 문제인가요?

문제는 세 가지였습니다.

① 약관: 무료 진열장은 사업 운영용이 아닙니다

GitHub Pages 공식 문서의 「사용 한도」 항목에는, 온라인 사업이나 전자상거래, 상업 거래를 위한 무료 웹 호스팅으로 쓰는 것을 허용하지 않는다고 적혀 있습니다. 같은 문서는 비밀번호나 카드 번호 같은 민감한 거래에도 쓰지 말라고 안내합니다.

우리 사이트에는 강의 판매, 서비스 판매 페이지, 광고 랜딩이 붙어 있었습니다.

② 연쇄 정지: 한 계정에 여러 사이트가 묶여 있습니다

홈페이지 제작사는 보통 계정 하나에 여러 사이트를 올립니다. 그 계정이 약관 문제로 멈추면 판매 기능이 없는 다른 사이트까지 같이 내려갈 수 있습니다. 한 사이트 때문에 전부가 멈추는 구조는 피해야 합니다.

한 계정에 묶인 사이트들

③ 보안 등급: 무료 진열장은 보안 머리글을 못 붙입니다

보안 머리글은 브라우저에게 「이 사이트에서는 우리 파일 말고 다른 스크립트는 실행하지 마라」, 「다른 사이트 안에 끼워 넣지 마라」 같은 규칙을 알려 주는 장치입니다. GitHub Pages에서는 이 머리글을 직접 붙일 방법이 없어서, 보안 점검에서 높은 등급이 나오지 않습니다. 우리는 모든 홈페이지를 보안 A+로 만든다는 원칙이 있었는데, 정작 우리 사이트가 그 기준에 못 미쳤습니다.

3. 어떤 선택지를 고민했나요?

A. 원래 계획대로 우리 서버B. Cloudflare Pages로 이사
보안 A+서버 설정으로 가능파일 하나(_headers)로 가능
추가 비용없음없음(무료 요금제)
걱정되는 점다른 서비스가 같은 서버를 써서, 서버가 멈추면 홈페이지도 같이 멈춤이사 과정에서 사장님(계정 주인) 손이 몇 번 필요
글 자동 발행그대로그대로(창고는 GitHub 유지)

B를 골랐습니다. 이미 다른 견본 사이트 여러 곳이 같은 방식으로 A+를 받고 있어 검증된 길이었고, 홈페이지가 다른 서비스와 운명을 같이하지 않게 할 수 있었습니다.

핵심은 창고와 진열장을 분리하는 것입니다. 글을 올리는 길(GitHub 저장소)은 그대로 두고, 손님에게 보여 주는 곳만 바꿨습니다. 그래서 글 발행 시스템은 한 줄도 고치지 않았습니다.

4. 어떻게 옮겼나요? (순서가 중요합니다)

1단계 — 새 진열장을 먼저 완성하고 점검까지 끝내기

손님이 아직 옛 진열장을 보는 동안, 새 진열장(Cloudflare Pages)에 사이트를 똑같이 올렸습니다. 보안 규칙은 _headers 파일 하나에 적었습니다. 임시 주소에서 미리 점검한 결과는 다음과 같습니다.

  • Mozilla Observatory 보안 등급 A+ (120점)
  • 홈페이지 점검 FAIL 0건
  • 첫 화면·판매 페이지·블로그·강의·글·관리 화면 6종에서 보안 규칙 때문에 막히는 곳 0건

2단계 — 창고에서 새 진열장으로 자동 배달 연결

새 글이 창고(GitHub)에 올라오면 새 진열장으로 자동으로 배달되도록 연결했습니다. 이 배달에는 Cloudflare 열쇠(토큰)가 필요합니다. 열쇠는 계정 주인이 직접 만들어 넣었습니다.

계정 단위 권한으로 시작

「Cloudflare Pages · 편집」 하나만 고름

열쇠에는 꼭 필요한 권한 하나만 줍니다. 목록에 「모든 자원 읽기」, 「열쇠 추가로 만들기」 같은 넓은 묶음이 보이지만 고르지 않습니다. 기한은 1년으로 두고, 만료 한 달 전 알림을 할 일 표에 넣었습니다.

3단계 — 도메인을 Cloudflare에 연결하기

「Connect a domain」 선택. Transfer·Buy는 돈이 나가는 메뉴

검색·AI 로봇 출입을 모두 허용

이 화면에서 AI 검색 로봇 출입을 막지 않도록 확인했습니다. 요즘은 ChatGPT·Claude 같은 AI가 답을 만들 때 홈페이지를 읽어 가는데, 여기서 막으면 AI 검색에 우리 홈페이지가 나오지 않습니다.

Cloudflare가 읽어 온 기존 주소 기록. 전부 GitHub 서버 주소

Cloudflare가 가져온 기존 기록 5줄은 모두 GitHub 진열장 주소였습니다. 이 5줄을 지우고 새 진열장 주소 2줄을 넣었습니다.

안내소는 「이 주소로 오는 손님을 어디로 보낼지」 알려 주는 곳입니다. 주소록(2~3단계)을 다 채운 뒤에 안내소를 바꿔야 합니다. 거꾸로 하면 새 안내소로 간 손님이 빈 주소록을 받아 사이트가 아예 안 열립니다.

결과 — 실제 주소에서 다시 잰 숫자

sotongmk.com 보안 등급 A+

  • 응답 머리글: Server: GitHub.com → Server: cloudflare, 보안 머리글 6종이 붙음
  • Mozilla Observatory 보안 등급 A+ (115점, 12개 시험 중 11개 통과)
  • 검색·AI 로봇 8종(구글·빙·네이버·다음·ChatGPT·Claude·퍼플렉시티·애플) 이름으로 접속 → 모두 정상(200)
  • 글 자동 발행은 그대로: 새 글이 저장소에 올라오면 약 30초 뒤 새 진열장에 반영

5. 우리가 실제로 빠졌던 함정 3가지

함정 1 — 비밀값 입력칸은 무엇이 들어갔는지 안 보입니다.

열쇠를 넣는 칸은 글자를 *로 가립니다. 처음에는 열쇠 대신 다른 글자(직전에 복사한 명령어)가 들어갔는데, 화면으로는 알 수 없었습니다. 「넣었다」에서 끝내지 않고 바로 시험 배포를 돌렸기 때문에 오류 번호를 보고 잡을 수 있었습니다. 그 뒤로는 클립보드에서 바로 꺼내 넣는 명령을 써서 붙여 넣기 실수가 생길 틈을 없앴습니다.

함정 2 — www 없는 주소는 「한 줄 수정」으로 안 됩니다.

www.주소는 국내 도메인 업체 화면에서 한 줄(CNAME)로 새 진열장에 연결할 수 있습니다. 하지만 www 없는 주소는 그런 연결을 허용하지 않는 경우가 많습니다. 그래서 안내소 자체를 Cloudflare로 옮겼습니다. 처음 예상보다 단계가 늘어난 이유입니다.

함정 3 — 안내소를 바꾼 직후 몇 분은 열리지 않을 수 있습니다.

인터넷의 안내소들은 예전 답을 한동안 기억합니다. 그래서 바꾼 직후에는 손님마다 옛 진열장과 새 진열장을 나눠서 봅니다. 새 진열장 쪽은 Cloudflare가 「이 도메인이 정말 나한테 왔다」를 확인하고 보안 인증서를 만들기 전까지 잠깐 열리지 않습니다. Cloudflare 화면의 「Check nameservers now」 버튼으로 이 확인을 앞당길 수 있습니다.

6. 사장님 홈페이지도 확인해 보세요

사장님 점검3가지

  1. 실제로 어디서 나가고 있나요? 만든 곳에 「제 홈페이지는 지금 어느 서버에서 보이나요?」라고 물어보세요. 계약서·안내서에 적힌 곳과 같아야 합니다.
  2. 무료 진열장에 판매 기능이 붙어 있지 않나요? 결제·주문·광고 랜딩이 있다면, 그 호스팅 약관이 사업 운영을 허용하는지 확인하세요.
  3. 보안 등급은 몇 점인가요? Mozilla Observatory(developer.mozilla.org/observatory)에 주소를 넣으면 무료로 등급이 나옵니다.

7. 무료 진열장은 쓰면 안 되나요?

그렇지 않습니다. 판매 기능 없이 가게를 소개하는 홈페이지라면 무료 진열장은 많이 쓰이는 방식이고, 빠르고 안정적입니다.

옮기는 게 좋은 경우

  • 결제·주문·상품 판매·광고 랜딩이 붙은 페이지
  • 보안 등급(A+)을 계약 조건이나 신뢰의 근거로 내세워야 하는 곳
  • 같은 계정에 다른 사이트가 많이 묶여 있는 경우

그대로 둬도 되는 경우

  • 가게 소개·오시는 길·소식 위주의 홈페이지
  • 예약·결제는 네이버 예약 등 외부 서비스로 연결만 하는 경우

소통마케팅센터는 이번 일을 계기로 우리가 만든 사이트 전체를 같은 기준으로 다시 점검하고 있습니다. 새로 만드는 홈페이지는 처음부터 보안 머리글을 붙일 수 있는 곳에 올리고, 판매 페이지와 소개 페이지를 같은 바구니에 담지 않는 것을 원칙으로 합니다.

자주 묻는 질문

Q. GitHub Pages가 뭔가요?

GitHub(개발자들이 코드를 보관하는 서비스)가 무료로 제공하는 홈페이지 진열 기능입니다. 저장소에 파일을 올리면 바로 홈페이지로 보여 줍니다.

Q. 이사하는 동안 홈페이지가 멈추나요?

대부분의 시간은 멈추지 않습니다. 새 진열장을 먼저 완성해 두고 안내소만 마지막에 바꾸기 때문입니다. 다만 안내소를 바꾼 직후 몇 분은 일부 방문자에게 보안 연결 오류가 보일 수 있습니다.

Q. 비용이 드나요?

이번 이사에서 추가 비용은 없었습니다. Cloudflare 무료 요금제를 썼고, 도메인은 원래 등록한 곳(가비아)에 그대로 두었습니다.

지금 가게 이름으로 검색해 보셨습니까?

상호와 업종만 남겨주시면 현재 온라인에서 어떻게 보이는지 정리해서 알려드립니다. 비용은 없습니다.
